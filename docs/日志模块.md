> 本文档说明 MsgFerry 的**日志模块**：业务日志（Logger）与审计日志（AuditLogger）的配置方式、日志路径解析、文件命名规则、内容格式，以及 MCP Server 与 Worker 两侧的使用示例。
>
> 核心结论：业务日志由 `LOG_SAVE` 控制开关、`LOG_DIR` 控制目录，默认落在 `<hgfs_root>/logs/mcp-server` 与 `<hgfs_root>/logs/worker`；文件名按北京时间精确到秒，内容为 `[时间戳] [级别] 消息` 的纯文本行；审计日志按日期分片、JSON 行存储，随任务记录并保留 30 天。

## 一、 模块概述

### 1. 模块组成与文件位置

日志模块分为**业务日志**与**审计日志**两大块，全部源码位于 `packages/shared` 与 `packages/worker` 两个包内。

#### 1.1 业务日志核心文件

| 文件 | 说明 |
| --- | --- |
| [logger.ts](../packages/shared/src/logger.ts) | `Logger` 类与全局单例，提供 `info()` / `error()` / `warn()` / `block()` |
| [log-config.ts](../packages/shared/src/log-config.ts) | `LOG_SAVE` 开关读取与 `LOG_DIR` 路径解析 |
| [timestamp.ts](../packages/shared/src/timestamp.ts) | 北京时间时间戳工具，统一文件名与行内时间格式 |
| [terminal-sanitizer.ts](../packages/shared/src/terminal-sanitizer.ts) | 终端输出清洗，剥离 ANSI 转义与控制字符 |

#### 1.2 日志辅助工具

| 文件 | 说明 |
| --- | --- |
| [constants.ts](../packages/shared/src/constants.ts) | 定义 `LOG_DIRS.mcpServer` 与 `LOG_DIRS.worker` 两个默认相对目录 |
| [log.ts](../packages/worker/src/log.ts) | Worker 侧业务日志单例，默认目录 `<hgfs_root>/logs/worker` |
| [audit.ts](../packages/worker/src/audit.ts) | `AuditLogger` 审计日志器，按日期滚动、可检索 |
| [clean-log.mjs](../scripts/clean-log.mjs) | 业务日志清理脚本（`pnpm clean-log`） |

#### 1.3 Worker 侧与 MCP 侧的使用

- **MCP Server** 直接使用共享包导出的全局单例 [`logger`](../packages/shared/src/logger.ts)，默认目录为 `<hgfs_root>/logs/mcp-server`；
- **Worker** 使用 [`log.ts`](../packages/worker/src/log.ts) 中带 `Worker` 标签的单例，默认目录为 `<hgfs_root>/logs/worker`；
- 两侧共用同一套 `Logger` 实现，仅默认目录与文件头部标识不同。

### 2. 日志的两大类别

#### 2.1 业务日志

面向开发与排障的运行日志，记录进程启停、任务流转、策略拦截、错误告警等过程信息。写入 `logs/` 目录下的 `.log` 文本文件，同时镜像输出到 `stderr`。

#### 2.2 审计日志

面向安全审计的任务记录，每条任务写一行 JSON，包含 `task_id`、命令摘要、策略结果、SSH 目标、退出码、耗时等信息。由 `AuditLogger` 负责写入、滚动与清理。

### 3. 设计要点

- **延迟初始化**：日志文件在首次写入时才创建，避免依赖模块加载时的环境变量时序；
- **不污染 stdio**：终端输出走 `stderr`，防止 MCP stdio 协议通道被日志破坏；
- **静默容错**：文件写入失败或 `stderr` 管道断开时静默忽略，不影响主流程。

## 二、 配置方式

### 1. 配置项总览

业务日志底层只依赖 3 个环境变量，无独立配置文件：

| 环境变量 | 作用 | 取值示例 |
| --- | --- | --- |
| `LOG_SAVE` | 是否启用文件保存 | `1` / `true` |
| `LOG_DIR` | 日志目录（绝对或相对路径） | `logs/worker`、`E:\logs`、`/var/log/msgferry` |
| `MSGFERRY_HGFS_ROOT` | HGFS 共享根目录，解析相对路径的基准 | `/mnt/hgfs/sharedir/vm_share` |

> **两侧取值方式不同**：
> - **MCP Server**：直接由启动环境提供这 3 个环境变量（`.mcp.json` / shell）；
> - **Worker**：环境变量配置已收敛，改为通过命令行 `--log-save` / `--log-dir`（配合必填的 `--hgfs-root`）传递，由 `main.ts` 在启动时注入 `process.env.LOG_SAVE` / `LOG_DIR` / `MSGFERRY_HGFS_ROOT` 供共享 Logger 延迟初始化读取——**日志模块本身不感知差异**。

### 2. Worker 侧配置（命令行）

Worker 为保证日志模块能正常初始化和及时写入日志，日志配置的两个字段走命令行参数，**不进入配置文件** `config/worker.json`：

| 命令行参数 | 作用 | 默认值 |
| --- | --- | --- |
| `--log-save` | 是否启用文件保存，取值 `1` / `true` | 不启用 |
| `--log-dir` | 日志目录（绝对原样 / 相对基于 hgfs_root） | `<hgfs_root>/logs/worker` |
| `--hgfs-root` | HGFS 共享根目录（必填，同时作为相对日志目录解析基准） | 无（必填） |

```bat
:: 开启业务日志，目录默认 <hgfs_root>/logs/worker
msgferry-worker --hgfs-root E:\MyLinux\VMware\sharedir\vm_share --log-save 1

:: 自定义日志目录（相对路径基于 hgfs_root 解析）
msgferry-worker --hgfs-root E:\MyLinux\VMware\sharedir\vm_share --log-save 1 --log-dir logs/worker
```

> `audit_log_dir` 字段保留但暂不提供配置入口，当前固定等于业务日志目录（`<hgfs_root>/logs/worker`）。

### 3. LOG_SAVE：日志保存开关

#### 2.1 取值规则

- 取值为 `1` 或 `true`（字符串）时启用文件保存；
- 其他取值（含未设置）均视为关闭。

判断逻辑见 `isLogSaveEnabled()`，在 [log-config.ts](../packages/shared/src/log-config.ts) 中实现。

#### 2.2 关闭时的行为

- `LOG_SAVE` 未开启时**不创建**日志文件，`logger.info()` 等方法只写 `stderr`，终端仍可见日志；
- 这保证了在未配置环境变量时，MCP 进程也能正常启动而不产生多余文件。

### 4. LOG_DIR：日志目录

`LOG_DIR` 支持三种写法，解析结果均为绝对路径：

#### 4.1 绝对路径

原样使用，不依赖 `hgfs_root`。典型场景：

- 外网 Windows 侧：`E:\MyLinux\VMware\sharedir\vm_share\logs`
- 内网 Linux 侧：`/var/log/msgferry`

#### 4.2 相对路径

基于 `MSGFERRY_HGFS_ROOT` 解析为绝对路径，未提供 `hgfs_root` 时回退到当前工作目录（`process.cwd()`）。示例：

- 设置 `MSGFERRY_HGFS_ROOT=/mnt/hgfs/sharedir/vm_share`、`LOG_DIR=logs/worker` 时，最终目录为 `/mnt/hgfs/sharedir/vm_share/logs/worker`。

#### 4.3 未设置时的默认值

- MCP Server：`<hgfs_root>/logs/mcp-server`（常量 `LOG_DIRS.mcpServer`）；
- Worker：`<hgfs_root>/logs/worker`（常量 `LOG_DIRS.worker`）；
- `hgfs_root` 也未配置时回退到 `./log`，保证 `Logger` 可独立使用。

### 5. MSGFERRY_HGFS_ROOT：共享根目录

- 仅作为相对路径解析的基准，本身不参与日志写入；
- MCP 与 Worker 两侧的 `hgfs_root` 指向**同一个物理共享目录**，只是各自用本系统的路径写法；
- MCP 侧由 `.mcp.json` / shell 环境变量提供；Worker 侧由 `--hgfs-root` 命令行参数提供并注入环境变量。

### 6. 配置示例

#### 6.1 MCP Server 示例

```bash
export MSGFERRY_HGFS_ROOT=/mnt/hgfs/sharedir/vm_share
export LOG_SAVE=1
export LOG_DIR=logs/mcp-server
npx msgferry-mcp-server
```

#### 6.2 Worker 示例

```bat
:: 日志配置走命令行（--log-save / --log-dir），由 Worker 注入环境变量供共享 Logger 读取
msgferry-worker --hgfs-root E:\MyLinux\VMware\sharedir\vm_share --log-save 1 --log-dir logs\worker
```

## 三、 日志路径解析规则

### 1. 解析优先级

`LOG_DIR` 的解析优先级从高到低：

1. `LOG_DIR` 为绝对路径 → 原样使用；
2. `LOG_DIR` 为相对路径 → 基于 `hgfs_root` 解析；
3. 未设置 `LOG_DIR` → 使用默认相对目录（`logs/mcp-server` 或 `logs/worker`）；
4. 未设置 `hgfs_root` → 回退 `./log`。

### 2. MCP Server 默认路径

```text
<hgfs_root>/logs/mcp-server/YYYY-MM-DD_HHMMSS.log
```

例如 `hgfs_root=/mnt/hgfs/sharedir/vm_share` 时：

```text
/mnt/hgfs/sharedir/vm_share/logs/mcp-server/2026-08-09_153000.log
```

### 3. Worker 默认路径

```text
<hgfs_root>/logs/worker/YYYY-MM-DD_HHMMSS.log
```

例如 `hgfs_root=E:\MyLinux\VMware\sharedir\vm_share` 时：

```text
E:\MyLinux\VMware\sharedir\vm_share\logs\worker\2026-08-09_153000.log
```

### 4. 路径解析函数

#### 4.1 resolveLogDir()

日志目录的最终解析由 `resolveLogDir()` 完成，该函数在 [log-config.ts](../packages/shared/src/log-config.ts) 文件中声明：

```ts
// packages/shared/src/log-config.ts
export function resolveLogDir(opts: {
  hgfsRoot?: string;
  logDir?: string;
  defaultRel?: string;
}): string {
```

【**函数作用**】

将 `LOG_DIR` 解析为最终绝对路径：绝对路径原样返回，相对路径基于 `hgfsRoot` 拼接，未设置时回退到默认相对目录（`defaultRel` 或 `LOG_DIRS.mcpServer`）。

【**参数含义**】

- `hgfsRoot`：HGFS 共享根目录，来自环境变量 `MSGFERRY_HGFS_ROOT`；
- `logDir`：用户配置的 `LOG_DIR`，可为绝对路径或相对路径；
- `defaultRel`：未设置 `LOG_DIR` 时的默认相对目录，缺省取 `LOG_DIRS.mcpServer`。

【**返回值**】

解析后的绝对日志目录字符串。

#### 4.2 isLogSaveEnabled()

日志保存开关的判断由 `isLogSaveEnabled()` 完成，该函数在 [log-config.ts](../packages/shared/src/log-config.ts) 文件中声明：

```ts
// packages/shared/src/log-config.ts
export function isLogSaveEnabled(env: NodeJS.ProcessEnv = process.env): boolean {
```

【**函数作用**】

读取环境变量 `LOG_SAVE`，取值为 `1` 或 `true` 时返回 `true`，表示启用文件保存。

【**参数含义**】

- `env`：进程环境变量对象，缺省为 `process.env`。

【**返回值**】

启用返回 `true`，否则返回 `false`。

### 5. 跨平台路径说明

- Worker 运行在外网 Windows 主机，日志目录与共享根目录使用 Windows 盘符路径（`E:\...`）；
- MCP Server 运行在内网 Linux，使用 HGFS 挂载路径（`/mnt/hgfs/...`）；
- 两侧日志可写到同一共享目录，便于内网侧直接查看外网产生的日志。

## 四、 日志文件命名规则

### 1. 业务日志文件名

#### 1.1 文件时间戳格式

文件名使用北京时间（Asia/Shanghai），格式为：

```text
YYYY-MM-DD_HHMMSS.log
```

- 日期部分用 `-` 分隔，便于肉眼识别；
- 时分秒紧凑无分隔符，缩短文件名；
- 字段从大到小且定宽，字典序等于时间序，便于按名排序。

由 `fileTimestamp()` 生成，见 [timestamp.ts](../packages/shared/src/timestamp.ts)。

#### 1.2 文件名示例

```text
2026-08-09_153000.log
2026-08-09_153005.log
```

每次进程启动写入新文件，多个文件按时间排序即可还原运行轨迹。

### 2. 审计日志文件名

#### 2.1 按日期分片

审计日志按 UTC 日期命名，格式为 `YYYY-MM-DD.log`，同一日期的多条任务记录追加到同一文件：

```text
logs/worker/2026-08-09.log
```

#### 2.2 大小滚动

单个文件超过上限（默认 10 MB）时按序号滚动：

```text
2026-08-09.log
2026-08-09_1.log
2026-08-09_2.log
```

### 3. 清理工具

业务日志可通过 `pnpm clean-log` 清理，脚本为 [clean-log.mjs](../scripts/clean-log.mjs)：

- 未设置 `LOG_DIR` 时清理 `logs/mcp-server` 与 `logs/worker` 两个默认目录；
- 设置 `LOG_DIR` 时仅清理其指向的目录；
- 目录基准依次取 `--hgfs-root` 参数 > `MSGFERRY_HGFS_ROOT` 环境变量 > 当前工作目录。

## 五、 日志内容格式

### 1. 业务日志行格式

#### 1.1 行内时间戳

每行以北京时间时间戳开头，格式为：

```text
[YYYY-MM-DD HH:mm:ss]
```

由 `logTimestamp()` 生成，例如：

```text
[2026-08-09 15:30:00]
```

#### 1.2 日志级别

支持 `INFO`、`WARN`、`ERROR` 三种级别，紧随时间戳：

```text
[2026-08-09 15:30:00] [INFO] MCP server ready, hgfs_root=/mnt/hgfs/sharedir/vm_share
```

#### 1.3 消息体

- 普通日志：多个参数以空格拼接，非字符串参数会被 `JSON.stringify` 序列化；
- 约定使用 `[模块]` 前缀标识上下文，如 `[worker]`、`[mcp-server]`、`[submit_ssh_task]`、`[housekeeping]`。

### 2. 日志文件头部

新文件或空文件时写入统一头部，用于标识文件来源与创建时间：

```text
=~=~=~=~=~=~=~=~=~=~=~= Mcp Server log 2026.08.09 15:30:00 =~=~=~=~=~=~=~=~=~=~=~=
```

- MCP Server 侧标签为 `Mcp Server`；
- Worker 侧标签为 `Worker`。

### 3. 内容块 block 格式

`block()` 用于输出带分隔线的结构化内容块，格式如下：

```text
[2026-08-09 15:30:00] [INFO] [policy] 命令安全策略校验结果:
----------------------------
    whitelist hit: docker
    action: allow
----------------------------
```

- 首行：`[时间戳] [级别] [上下文] 描述:`；
- 分隔线：连续 28 个 `-`；
- 内容行缩进 4 个空格；
- 支持 `maxLines` 截断：超过上限时保留头尾、省略中间行并标注 `[N lines omitted]`。

### 4. 终端输出清洗

日志写入文件前统一经过 `sanitizeLine()` 清洗，保证日志文件为纯文本。

#### 4.1 清洗策略

1. ANSI CSI 序列（`\x1b[...m` 等）替换为 `[CSI]` 标记；
2. OSC 序列（`\x1b]...BEL`）替换为 `[OSC]`；
3. 其他 ANSI 序列替换为 `[ANSI]`；
4. 移除回车符 `\r`；
5. 其余非打印控制字符（0x00-0x08、0x0B-0x0C、0x0E-0x1F、0x7F）替换为可见标记，如 `[ESC]`、`[BEL]`。

#### 4.2 sanitizeLine()

清洗函数在 [terminal-sanitizer.ts](../packages/shared/src/terminal-sanitizer.ts) 文件中声明：

```ts
// packages/shared/src/terminal-sanitizer.ts
export function sanitizeLine(line: string): string {
```

【**函数作用**】

将可能包含 ANSI 转义与控制字符的日志行清洗为安全纯文本，供日志文件使用。

【**参数含义**】

- `line`：原始日志行，可能含 ANSI 颜色、光标控制序列与回车符。

【**返回值**】

清洗后的纯文本行，保留制表符 `\t` 与换行符 `\n`。

### 5. 审计日志格式

#### 5.1 JSON 行格式

审计日志每行一个 JSON 对象，`AuditLogger` 写入时补充 `system_time` 字段：

```json
{"task_id":"t_20260809_153000_abc","cmd_summary":"docker ps","policy_result":{"allowed":true,"reason":null},"ssh_target":"192.168.1.100","exit_code":0,"duration_ms":320,"cancelled":false,"timestamp":1723181400000,"system_time":"2026-08-09 15:30:00"}
```

#### 5.2 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | string | 任务唯一标识 |
| `cmd_summary` | string | 命令摘要，最长 200 字符 |
| `policy_result` | object | 策略校验结果（`allowed`、`reason` 等） |
| `ssh_target` | string / null | SSH 目标主机，mock 模式为 `null` |
| `exit_code` | number / null | 命令退出码 |
| `duration_ms` | number | 任务耗时（毫秒） |
| `cancelled` | boolean | 是否被取消 |
| `timestamp` | number | 毫秒 epoch 时间戳 |
| `system_time` | string | 本地时区时间，格式 `YYYY-MM-DD HH:MM:SS` |

## 六、 代码实现与示例

### 1. Logger 类

`Logger` 类在 [logger.ts](../packages/shared/src/logger.ts) 文件中声明：

```ts
// packages/shared/src/logger.ts
export class Logger {
  constructor(
    private readonly defaultRel?: string,
    private readonly label: string = 'Mcp Server',
  ) {}
```

【**函数作用**】

业务日志记录器，提供 `info()` / `error()` / `warn()` / `block()` 方法，写入日志文件的同时镜像输出到 `stderr`。

【**参数含义**】

- `defaultRel`：未设置 `LOG_DIR` 时的默认相对日志目录，缺省取 `LOG_DIRS.mcpServer`；
- `label`：日志文件头部标识，MCP 侧缺省为 `Mcp Server`，Worker 侧传入 `Worker`。

【**返回值**】

无（构造函数）。

#### 1.1 延迟初始化机制

- 首次写入日志时调用 `ensureInit()`；
- 此时才检查 `LOG_SAVE`、解析目录、创建目录与文件；
- 避免模块加载阶段环境变量尚未就绪导致解析错误。

#### 1.2 全局单例

```ts
// packages/shared/src/logger.ts
export const logger = new Logger();
```

### 2. 输出方法

#### 2.1 info()

普通信息日志，该方法在 [logger.ts](../packages/shared/src/logger.ts) 中声明：

```ts
// packages/shared/src/logger.ts
info(...args: unknown[]): void {
```

【**函数作用**】

记录普通运行信息，写入日志文件并输出到 `stderr`。

【**参数含义**】

- `args`：任意数量参数，字符串直接拼接，非字符串 `JSON.stringify` 序列化。

【**返回值**】

无。

#### 2.2 error()

错误日志，该方法在 [logger.ts](../packages/shared/src/logger.ts) 中声明：

```ts
// packages/shared/src/logger.ts
error(...args: unknown[]): void {
```

【**函数作用**】

记录错误信息，级别为 `ERROR`，用于异常与失败场景。

【**参数含义**】

- `args`：同 `info()`，通常第一个参数为错误描述，后续可传 `Error` 对象。

【**返回值**】

无。

#### 2.3 warn()

警告日志，该方法在 [logger.ts](../packages/shared/src/logger.ts) 中声明：

```ts
// packages/shared/src/logger.ts
warn(...args: unknown[]): void {
```

【**函数作用**】

记录警告信息，级别为 `WARN`，用于超时、取消、心跳失败等非致命问题。

【**参数含义**】

- `args`：同 `info()`。

【**返回值**】

无。

#### 2.4 block()

结构化内容块日志，该方法在 [logger.ts](../packages/shared/src/logger.ts) 中声明：

```ts
// packages/shared/src/logger.ts
block(
  level: string,
  context: string,
  description: string,
  content: string,

```

【**函数作用**】

写入带分隔符的内容块到日志文件与终端，适用于策略校验结果、任务输出等多行内容。

【**参数含义**】

- `level`：日志级别（`INFO`、`WARN`、`ERROR`）；
- `context`：上下文标识（如 `policy`、`task`），为空时省略 `[context]`；
- `description`：块描述或标签；
- `content`：块内容，多行文本；
- `maxLines`：最大保留行数，正数表示截断省略中间行，`-1` 表示全部显示（默认）。

【**返回值**】

无。

## 七、 注意事项与常见问题

### 1. 为何输出到 stderr

- MCP Server 通过 stdio 与 Claude Code 通信，stdout 是协议通道；
- 日志写 stdout 会破坏 JSON-RPC 消息解析，因此**所有终端输出统一走 stderr**；
- Worker 与 MCP 的日志均遵守此约定。

### 2. 写入失败静默处理

- 文件写入失败（权限、磁盘满等）时静默吞掉异常，不影响任务主流程；
- `stderr` 管道断开（MCP 客户端掉线）时同样静默忽略，避免 EPIPE 死循环。

### 3. 日志文件延迟创建

- 只有首次调用输出方法时才创建目录与文件；
- 因此仅设置 `LOG_SAVE=1` 但从未产生日志时，目录不会出现。

### 4. 常见问题

**问题 1：设置了 `LOG_SAVE=1` 但没看到日志文件？**

检查 `MSGFERRY_HGFS_ROOT` 是否指向了正确的共享目录，以及进程是否真的调用了日志方法（如启动打印）。也可在启动日志中查看 `log_dir` 的实际解析结果。

**问题 2：日志目录解析到了错误位置？**

`LOG_DIR` 为相对路径时基于 `hgfs_root` 解析，请确认两侧各自的 `hgfs_root` 写法（Windows 盘符 / Linux 挂载路径）。

**问题 3：日志里出现 `[CSI]`、`[OSC]` 标记？**

这是 `sanitizeLine()` 把 ANSI 转义序列替换为可见标记的结果，属于预期行为，说明原始输出含终端控制序列，文件本身仍是纯文本。

**问题 4：如何快速清理历史日志？**

在 Worker 或 MCP 运行环境执行 `pnpm clean-log`，或直接删除 `logs/mcp-server`、`logs/worker` 目录。
